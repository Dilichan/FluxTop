# Автозапуск при входе в Windows

Реализована настройка клиента «Автозапуск при входе в Windows (с запросом UAC)».
По умолчанию выключена; сборка проекта ничего не регистрирует.
Это вход текущего пользователя, а не служба до входа в систему.

## Скачиваемый EXE

Установщик FluxTop.exe размещает независимый launcher в `%LOCALAPPDATA%\FluxTop\FluxTop.exe`.
Клиент регистрирует ярлык именно на него с аргументом --autostart.
Установщик не включает автозапуск автоматически. Если уже существует собственный ярлык
автозапуска FluxTop, установщик обновляет только его путь, сохраняя отключение через
Windows StartupApproved. Git, VBS и
PowerShell для этого режима не нужны. Launcher ждёт 30 секунд, проверяет
GitHub Releases, затем запрашивает UAC и запускает монитор с --overlay --tray.
Запрос подтверждается при каждом входе. Обновления не очищают БД.

## Запуск из исходников через Git

1. Клиент создаёт управляемый ярлык FluxTop.lnk в пользовательской папке Startup.
2. Ярлык запускает системный wscript.exe и tools/Start-FluxTop.vbs из репозитория.
   Скрипт открывает PowerShell launcher скрыто, без постоянного окна консоли.
3. Start-FluxTop.ps1 -Autostart ждёт 30 секунд, проверяет Git и готовит версию
   по обычным правилам. Диагностика: out/launcher/autostart.log.
   Интерактивные запросы Git/GCM отключены; ошибки используют предыдущий EXE.
4. Только подготовленный монитор запускается через RunAs с запросом UAC.
   Пользователь подтверждает его вручную. Отказ завершает запуск с кодом 1223,
   но не отключает автозапуск и следующую попытку обновления.
5. Аргументы --overlay --tray оставляют клиент закрытым и показывают таблицу/трей.
   Именованный mutex предотвращает второй новый экземпляр оверлея в той же
   пользовательской сессии. Launcher завершается после Start-Process.

Настройка не создаёт задачу с сохранённым повышением и не обходит UAC.
Запрос при каждом входе намеренный. Windows может задерживать Startup.
Без Windows Script Host/VBScript bootstrap не запустится; fluxtop.cmd остаётся
доступен. Задержка пока фиксированная, 30 секунд.

## Включение и выключение

Клиент показывает наличие своего ярлыка и учитывает отключение через
StartupApproved в Windows. Автозапуск не восстанавливается самопроизвольно.
Явное повторное включение сбрасывает только запись одобрения FluxTop.lnk.
Выключение удаляет только собственный ярлык с маркером FluxTop autostart v1;
чужой ярлык с таким именем не перезаписывается. Для пользовательской папки
Startup права администратора не нужны; они нужны при старте монитора.
Перед удалением проекта выключите автозапуск в клиенте.

Ярлык ссылается на стабильный bootstrap, не на build/ или версию EXE.
Перенос репозитория требует выключить/включить настройку для обновления пути.
Пути с пробелами и кириллицей передаются в кавычках. Программа ищет bootstrap
выше своего EXE до папки с fluxtop.cmd и tools/Start-FluxTop.vbs.
Отдельный EXE без репозитория не может зарегистрировать автозапуск.

## Проверки и оставшиеся задачи

Разработческие тесты не включают автозагрузку на компьютере. Полный вход после
перезагрузки требует ручной проверки; UAC не подтверждается автоматизацией.
Протокол ready/timeout/fallback после раннего падения ещё запланирован:
[ADR-0001](decisions/0001-independent-updater.md). Независимая проверка обновлений
перед запуском уже есть: [UPDATING.md](UPDATING.md).

Основания: [Startup apps](https://support.microsoft.com/en-gb/windows/experience/startup-boot/configure-startup-applications-in-windows?nochrome=true),
[RunAs / UAC](https://learn.microsoft.com/en-us/windows/win32/secbp/running-with-administrator-privileges).
