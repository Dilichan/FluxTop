# Автозагрузка при старте Windows

**Статус:** запланированная функция этапа «Сцены и трей».
В текущем консольном прототипе управление автозагрузкой не реализовано.
Этот документ задаёт требования; запись автозагрузки на компьютере не создаётся.

## Пользовательское поведение

- Настройка «Запускать FluxTop при входе в Windows», по умолчанию выключена.
- Запуск после входа текущего пользователя в Windows 10/11, включая вход после
  перезагрузки. Работа до входа пользователя и системная служба не требуются.
- Старт в трей без окна настроек и консоли; видимость оверлея берётся из
  сохранённого глобального профиля, затем применяются сцены приложений.
- Настраиваемая задержка старта: по умолчанию 30 секунд, диапазон 0–300 секунд.
  Ожидание не должно блокировать вход в Windows и не должно использовать busy loop.
- При уже работающем экземпляре второй монитор не запускается.
- Выключение настройки удаляет только запись автозапуска FluxTop текущего
  пользователя. Удаление приложения также должно предусматривать её удаление.

## Способ регистрации

Планируется ярлык в пользовательской папке автозагрузки Windows, указывающий
на стабильную точку запуска FluxTop. Регистрация не требует прав администратора
и не затрагивает автозагрузку других пользователей.

Ярлык не должен указывать на временный build-каталог или конкретную версию
из `out/launcher/versions/`: обновление EXE не должно ломать автозапуск.
Он указывает на независимый updater/launcher, чтобы падение монитора до
инициализации не мешало при следующем входе получить исправление из Git.
Пути и аргументы должны корректно обрабатывать пробелы и кириллицу.
Перенос папки приложения требует обновления ярлыка; настройка должна выявлять
устаревший путь и предлагать восстановить запись.

Настройки должны показывать фактическое состояние записи, в том числе её
отсутствие или отключение средствами Windows. Повторное включение не создаёт
дублирующихся ярлыков; внешнее отключение не отменяется автоматически.

## Связь с автообновлением

Автозапуск использует стабильный launcher с отдельным фоновым режимом,
который предстоит реализовать. Текущий `fluxtop.cmd` рассчитан на консольный
прототип и пока не обеспечивает скрытый запуск в трей.

Сохраняется проверка обновлений при старте через Git; для автозапуска нужна
отдельная настройка «Проверять обновления при входе в Windows», по умолчанию
включённая. Проверка выполняется после задержки старта. Действуют те же
правила: доверенный upstream, только fast-forward, сохранение локальных правок,
тестирование новой сборки и запуск предыдущего EXE при ошибке.

Отсутствие сети не вызывает диалогов и не мешает запуску имеющейся рабочей
версии. Если рабочая версия ещё не подготовлена, автозапуск записывает ошибку
в локальный журнал; первоначальную настройку и подготовку пользователь
выполняет обычным запуском. Фоновый режим не показывает терминал сборки,
запросы учётных данных и запросы повышения прав.

В целевой архитектуре launcher завершается после подтверждения готовности
монитора; ожидание ограничено timeout. Сбой монитора не отключает запись
автозагрузки и проверку обновлений при следующем входе. Постоянно работающий
updater не требуется. См. [ADR-0001](decisions/0001-independent-updater.md)
и [автообновление](UPDATING.md).

## Критерии готовности

1. Включение, выключение и повторное включение без дубликатов и повышения прав.
2. Вход после перезагрузки Windows 10/11: один экземпляр, трей, сохранённый профиль.
3. Корректные задержка, пути с пробелами/кириллицей и перенос папки приложения.
4. Офлайн-старт, ошибка обновления и уже работающий экземпляр без лишних окон.
5. Выход launcher-а после старта; его процессы отсутствуют в постоянном бюджете.
6. Удаление записи, внешнее отключение средствами Windows и восстановление пути.
