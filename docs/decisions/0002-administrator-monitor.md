# ADR-0002: административный режим монитора

**Статус:** принято; основной путь запуска запрашивает повышение через UAC.

## Решение

Запуск из исходников через `FluxTopSource.exe` подготавливает версию и
запускает монитор отдельным процессом через Win32 ShellExecuteExW с `runas`.
Установленный `FluxTop.exe` также использует стандартный запрос UAC. Пользователь подтверждает стандартный запрос UAC Windows.
Отказ завершает запуск с кодом 1223; повторных запросов и скрытого перехода
к ограниченному режиму нет. UAC и системные политики не изменяются.

Git, CMake и тесты не требуют административных прав. Launcher следует запускать
из обычной консоли: он запрашивает повышение только для готового EXE после
подготовки. Если сам launcher запущен из административной консоли, его дочерние
сборочные процессы наследуют эти права; принудительное понижение не выполняется.

Для тестов, автоматизации и работы без запроса повышения предусмотрен
`--standard-user` (также `-StandardUser`) у исходного launcher-а: монитор
получает унаследованные права. Прямой EXE также
наследует токен родителя. Эти пути не понижают уже повышенные права родителя.

## Доступ к метрикам

Монитор определяет фактический уровень своего токена. При повышенном токене
пытается включить уже назначенную `SeDebugPrivilege` для чтения метрик процессов.
Результат проверяется, включая `ERROR_NOT_ALL_ASSIGNED`; привилегия не добавляется
в политику учётной записи. Ошибка не останавливает доступные CPU/RAM-метрики.

Запросы к процессам сохраняют права, необходимые для чтения метрик.
Администратор и `SeDebugPrivilege` расширяют доступ, но не гарантируют чтение
защищённых процессов/PPL или аппаратных датчиков. Неизвестное остаётся `null`.
Драйвер, SYSTEM-служба, инъекции и обход защит не входят в решение.
В текстовом выводе и JSONL показываются фактические `elevated` и
`debug_privilege_enabled`; неизвестный статус токена отражается как `null`.

## Обновление и автозагрузка

Независимость updater-а от запуска монитора сохраняется: UAC вызывается после
проверки обновлений. При отказе UAC следующая попытка снова может получить фикс.
Повышенный консольный EXE открывается в отдельном окне; перенаправление stdout
launcher-а не захватывает его вывод. Для JSONL в pipeline используйте
`-StandardUser` или прямой EXE из консоли с нужными правами.

Автозагрузка реализована через пользовательский ярлык и отдельный bootstrap:
обновление идёт скрыто, перед запуском монитора пользователь подтверждает UAC.
Запрос появляется при каждом входе; заранее разрешённое повышение не создаётся.
Подробнее о запуске и правах: [UPDATING.md](../UPDATING.md).

## Проверки

- Сборка и CTest без интерактивного повышения.
- Выбор `RunAs` по умолчанию, унаследованный режим и распознавание отказа UAC.
- Проверки launcher-а с `-StandardUser`, включая fallback и cache.
- Ручная проверка UAC: подтвердить / отменить, затем сверить токен и метрики.
  Автотесты не подтверждают диалог за пользователя.
