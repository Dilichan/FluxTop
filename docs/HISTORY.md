# Хранение статистики FluxTop 0.2.4

## Единая SQLite-база

Путь: `%LOCALAPPDATA%\FluxTop\fluxtop.db`.

`fluxtop.db` содержит таблицы:

- `applications` — идентичности приложений;
- `history_rollups` — минутные, часовые и суточные агрегаты;
- `history_state` — временные границы и количество наблюдений;
- `icons` — кеш PNG-иконок по EXE-пути.

`fluxtop.db-wal` и `fluxtop.db-shm` — служебные файлы SQLite в режиме WAL.
Они не являются отдельными БД. Нельзя удалять их, пока запущен FluxTop.

## Конвейер

Настроенный интервал мониторинга 1–10 секунд не меняется. Для каждой минуты
в оперативной памяти хранятся только компактные статистические аккумуляторы
по приложениям; полные секундные снимки процессов не сохраняются на диск.

По завершении UTC-минуты результирующие значения записываются в SQLite.
По завершении UTC-часа объединяются минутные строки, а по завершении суток —
часовые. Хранятся суточные агрегаты за 3660 дней. Пустые периоды для
неработавших приложений не создаются. Среднее считается как сумма
`показатель × валидная длительность` / сумма валидных длительностей;
минимумы и максимумы объединяются независимо. Аптайм учитывает фактическое
наблюдаемое время без удвоения из-за нескольких дочерних процессов.

Фоновый поток осуществляет SQLite-запись, свёртку, checkpoint и частичный
`incremental_vacuum`. Очередь ограничена 8 минутами и приблизительно 2 МиБ.
При превышении лимита возникает видимая ошибка истории; сбор ресурсов
продолжается. История останавливается при угрозе превышения 50 ГиБ
(предварительная остановка при 49 ГиБ, включая WAL и SHM).

## Общий журнал событий

`activity.log` — единый журнал событий мониторинга, клиента, загрузчика и
операций SQLite. Время записывается по локальным часам Windows в ISO 8601
со смещением UTC (например, `2026-11-20T12:38:56.865+03:00`), затем следуют
PID, TID, уровень, категория и сообщение. Старые записи с суффиксом `Z`
сохраняются в UTC; ранее созданные журналы не переписываются.

Сохраняются последние 500 МиБ логов: активный `activity.log` плюс четыре
архивных сегмента `.1`–`.4` по 100 МиБ. Очередь логгера ограничена 256 КиБ;
перегрузка фиксируется сообщением `log.backpressure` с числом пропусков.

Логи не подменяют историю: детальные показатели всех процессов не пишутся
в журнал каждую секунду; пишутся диагностические события каждого цикла,
состояние SQLite, ошибки, изменения настроек и действия интерфейса.


## Совместимость

0.2.4 не мигрирует данные от 0.2.3. Старые файлы `history.db` и `icons.db`
не используются и не удаляются автоматически. Для полной очистки требуется
закрыть приложение и удалить старые файлы отдельно. Новые данные создаются
в `fluxtop.db`.
