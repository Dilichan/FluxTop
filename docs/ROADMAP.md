# План разработки

Этапы выполняются последовательно. Документация и выбор стека предшествуют коду.

| Этап | Результат | Критерий готовности |
| --- | --- | --- |
| 0. Проектирование | Требования, стек, архитектура, правила открытого репозитория | Границы MVP и методика замеров записаны |
| 1. Сборщик | C++20 CLI: CPU/RAM, optional GPU/memory, сортировка, JSONL, self metrics | Собирается на Windows, тесты и smoke test проходят; фактические замеры записаны |
| 2. Оверлей | Win32 + Direct2D/DirectWrite, таблица и иконки, DPI, прозрачность | Реальные данные, корректный resize и два монитора, нет постоянного render loop |
| 3. Сцены и трей | Глобальный профиль, EXE-профили, foreground hook, настройки по запросу, опциональная автозагрузка с Windows | Переключение по событию, настройки освобождаются при закрытии; автозапуск в трей без консоли, задержка, один экземпляр, отключение без прав администратора |
| 4. Расширение | Lazy ETW для сети/диска, датчики, оповещения | Накладные расходы каждого источника замерены отдельно, корректные fallback |
| 5. История | SQLite, retention, агрегации, просмотр статистики | Ограниченные cache/очередь, миграции и восстановление после аварии |
| 6. Проверка | Длительные замеры, утечки, Windows 10/11, игровые режимы | Результаты с конфигурациями опубликованы; цели подтверждены либо ограничения явно указаны |

## Ближайшие задачи после прототипа

Отдельная обязательная задача механизма обновлений: выполнить
[ADR-0001](decisions/0001-independent-updater.md) полностью — добавить сигнал
готовности, timeout и fallback при провале старта. Проверить сценарий:
неисправный EXE → следующий запуск updater-а → commit с фиксом → рабочий монитор.
Внешний launcher уже существует; подтверждение старта пока не реализовано.

1. Сравнить Tool Help/PSAPI с пакетным backend на машине с большим числом процессов.
2. Проверить PDH на RU/EN Windows и с несколькими GPU.
3. Прогнать CPU-нагрузку известного процесса и сравнить с Task Manager.
4. Отдельно проверить lifecycle: выход процесса во время сбора, запрет доступа,
   повторное использование PID и появление новых GPU-экземпляров.
5. Выбрать путь прозрачного рендеринга и проверить его бюджет перед расширением UI.

## Условия первого публичного релиза

Рабочий оверлей и трей, документированные ограничения, проверенная сборка,
известные проблемы, лицензии зависимостей и воспроизводимые измерения.
Первый CLI-прототип — техническая основа, а не обещание готового продукта.
