# План разработки FluxTop

Этот документ — **очередь следующих патчей**, а не журнал уже завершённых задач.
Сделанное отражается в коде, тестах и `docs/RELEASE_NOTES.md`. План корректируется
после каждого завершённого патча: выполненные пункты удаляются из очереди,
нерешённые переносятся в следующий этап с причиной. Новые документы под патчи не создаются.

## Что уже реализовано и не планируется повторно

- Нативный C++20 сборщик, Win32-клиент и оверлей; группирование процессов,
  CPU/RAM, GPU/GPU RAM, сетевые и дисковые сборщики, SQLite-история и графики.
- Отдельные тесты для core, history, statistics, temperatures, disk attribution,
  network и JSONL; Windows CTest вызывается в GitHub Actions.
- Нативные launcher, updater, установка и удаление; существующие механизмы
  сохраняются, но отдельные гарантии отказоустойчивости ещё требуют проверки.

Наличие реализации и теста **не является подтверждением** корректности на всех
конфигурациях. Особенно это относится к CPU-датчикам, ETW-атрибуции, частичной
достоверности показателей и жизненному циклу процессов.

## Обязательный шлюз качества для каждого патча

1. До изменений: зафиксировать базовый commit, чистоту Git, CTest Release и
   проверяемый сценарий; отметить уже падающие/пропущенные проверки.
2. Для бага: сначала создать воспроизводящий его тест, который падает на
   старой логике; для новой функции — положительные, граничные и негативные тесты.
3. Проверить контракт между затронутыми системами: сборщик → `Snapshot` →
   агрегатор → AutoScore/сортировка → оверлей/статистика → SQLite/JSONL.
   Для изменений UI — дополнительно проверять управление, паузу и отрисовку.
4. Не менять семантику `nullopt`/`null`, подтверждённого нуля, нижней границы
   `≥`, PID+время создания и идентичности приложения без явного теста.
5. После изменений: пересборка Release, полный CTest, целевые многократные
   интеграционные тесты и проверка сценария вручную, если он аппаратный/UI.
   Пропуск ETW без администратора — не эквивалент пройденного ETW-теста.
6. При падении теста — исправить причину или явно остановить патч; не
   ослаблять assert, не отключать тест и не удалять старую функциональность
   для получения «зелёного» результата. Не коммитить до прохождения шлюза.
7. Для рискованных изменений повторять контроль памяти/CPU/handles и
   корректности SQLite после остановки, перезапуска и частичного сбоя.

Постоянные правила для разработчиков — в `CONTRIBUTING.md`; перечень сценариев
и методика ресурсов — в `docs/PERFORMANCE.md`.

## v37 — базовая защита от регрессий (P0)

**Цель:** сделать проверку взаимодействий обязательной и исполняемой.

- Расширить `tests/` реальными unit, contract и integration тестами для
  доступности измерений, группирования, AutoScore, SQLite, JSONL и UI-политик.
- Проверить после v36.1: одинаковые имена без EXE-пути, повторное использование
  PID, связанное дерево процессов, подтверждённый ноль и полностью неизвестные
  данные; проверить чтение SQL по именам/индексам столбцов, аптайм и графики.
- Поставить CTest timeout и диагностику зависшего дочернего процесса; проверить
  сценарий принудительного зависания JSONL, не только успешный запуск.
- В CI обеспечить выполнение полного тестового набора в Release и строгую
  обработку FAILED; аппаратные и административные сценарии вести отдельно.
- Подготовить повторяемый smoke-сценарий: клиент, оверлей, остановка, запуск,
  перезапуск и чтение прежней базы без удаления пользовательской истории.

**Готово:** новые тесты действительно ловят намеренно внесённые нарушения;
CTest полностью проходит, а пропуски явно перечислены.

## v38 — достоверные дисковые показатели каждого процесса (P1)

- Проследить цепочку ETW DiskIo/FileIo → IRP/поток/PID → время создания →
  физический том → интервал → показания конкретного приложения.
- При отсутствии событий, недоступной ETW-сессии, потере событий и частичной
  атрибуции не публиковать неподтверждённые `0 Б/с`.
- Отдельно подтвердить read/write и сумму, а также `Disk C`, `Disk D` и
  общий «Диски»; не складывать один физический I/O дважды.
- Проверить несколько томов на одном диске, процессы с одинаковым именем,
  PID reuse, системный PID, кешированный I/O, отсутствие прав и исчезновение
  процесса между сбором и отображением.
- Добавить unit-тесты границ диапазонов/покрытия, интеграционные тесты ETW
  под администратором и тест доставки значения до оверлея.

**Готово:** каждое отображённое значение имеет проверяемый источник;
`—`, `0` и `≥` различаются корректно; суммы подтверждённых байтов сходятся.

## v39 — CPU temperature: надёжный выбор датчика (P1)

- Проверить реальные источники CPU Package/Tctl/Tdie и отдельно обозначаемые
  CPU Socket/board/ACPI; не подменять температуру кристалла датчиком платы.
- Проверить HWiNFO Shared Memory и WMI-совместимые источники из текущей
  реализации: отсутствие источника, недоступные права, выход мониторинга,
  устаревшие показания, несколько процессоров/датчиков и переподключение.
- Отбрасывать неверные/устаревшие значения; показывать `—`, если валидного
  измерения нет; не выдумывать универсальный температурный датчик Windows.
- Сохранить имеющуюся семантику GPU temperature, цвета и статус источника.
- Unit-тесты приоритетов, типов датчика и ошибок; интеграционные проверки
  на доступном оборудовании с указанием источника и контрольного ПО.

**Готово:** измерение воспроизводимо, источник известен, fallback обозначен,
потеря датчика не превращается в ноль и не оставляет старую температуру.

## v40 — единое правило Disk AutoScore (P1)

- Определить и закрепить контракт для общего «Диски» и выбранных `Disk X`:
  скрытые тома не должны влиять на сортировку, когда выбраны только другие.
- Явно разграничить пользовательскую сортировку и независимую историческую
  запись AutoScore; история не должна задним числом менять шкалу/смысл.
- Проверить общий/отдельный столбец, пустой набор, неизвестное покрытие,
  одновременные тома и переключение видимости без изменения сырых ETW-данных.
- Добавить contract-тесты на одинаковую трактовку данных в сортировке,
  оверлее, статистике и SQLite.

**Готово:** выбор томов предсказуемо влияет только на нужный рейтинг;
диск C не поднимает приложение при выборе только диска D.

## v41 — автомасштаб истории без потери пиков (P1)

- Проверить реальный диапазон и включённый/выключенный автомасштаб,
  включая единичные выбросы в начале суток.
- Ввести устойчивую шкалу для типичной нагрузки; явно обозначать значения,
  которые выходят за верхнюю границу, не выдавая отсечение за отсутствие пика.
- Проверить крайние случаи: 0, 100, один сэмпл, короткий/длинный диапазон,
  переходы через границы, пауза, масштаб и отдельное окно.
- Тестировать расчёт границ на числовых наборах, а не только наличие флажка.

**Готово:** на истории 0–20 с редким пиком 100 видна полезная шкала и
отмечен пик; выключение автомасштаба возвращает ручной режим.

## v42 — согласованное управление графиками (P2)

- Сопоставить `auto_scale_`, `system_autoscale_`, `PopupState`, паузу и
  настройки встроенного/вынесенного графика; выделить общую семантику,
  не переписывая работающий `draw_chart_core()` без необходимости.
- Проверить синхронизированные и намеренно независимые состояния;
  исключить неожиданные сбросы масштаба/паузы при смене вкладки или окна.
- Написать behavioral-тесты переходов состояний и UI smoke с реальным
  пользовательским действием, а не поиском текстовых обработчиков в исходнике.

**Готово:** одна операция имеет одинаковую задокументированную семантику
во всех графиках, при этом независимые состояния сохраняются где нужно.

## v43 — понятность показателей и диагностика (P2)

- Убрать ошибочные двоеточия в подписях `Disk C` без ломания обозначений
  путей/томов; явно различать системные PDH `% Disk Time` и процессные ETW MiB/s.
- Добавить в JSONL доступные проверенные дисковые поля и статус/покрытие,
  сохранив обратную совместимость существующего JSONL-контракта (schema/version
  менять только при настоящем несовместимом изменении).
- Проверить сохранение подписей, пустых/неизвестных значений, единиц и
  согласование JSONL с оверлеем и диагностическим журналом.

**Готово:** данные независимо проверяются через JSONL, а UI не смешивает
проценты активности диска и физическую скорость операций приложения.

## v44 — итоговая регрессия и стоимость ресурсов (P1)

- Прогнать весь Release CTest, административные ETW-сценарии, JSONL,
  базу с историей до обновления, запуск/закрытие клиента и оверлей.
- Сравнить CPU, Working Set, Private Bytes и handles в сценариях из
  `docs/PERFORMANCE.md`; проверить 8-часовую работу и возврат клиента в трей.
- Проверить Windows 10/11, DPI и несколько мониторов в доступных средах;
  результаты, которые не удалось воспроизвести, отметить как непроверенные.
- Проверить, что GPU/GPU RAM, сеть, анимации и прежние функции сохранились.

**Готово:** нет необъяснённых регрессий, тесты полные, ограничения и результаты
замеров отражены в фундаментальной документации и release notes.

## Отдельные будущие обязательства (после v44 или при блокирующем дефекте)

- Довести ADR-0001 независимого updater: ready handshake, timeout, fallback
  на последнюю рабочую сборку и сценарий «сломанный EXE → обновление → запуск».
- Проверить отдельными приёмочными тестами Windows 10/11, несколько GPU,
  защищённые процессы и игровые режимы; не считать успех CI достаточным.
- Профили/сцены для отдельных приложений и расширенные оповещения вести
  отдельной задачей после стабилизации измерений.

## Очередь стабилизации v37–v47

Выполнять строго по одному патчу: изменение → Release-сборка → полный CTest →
регрессия соседних подсистем → ручная проверка затронутых сценариев → коммит.

| Патч | Цель | Критерий приёмки |
| --- | --- | --- |
| v37 | Обязательные поведенческие и регрессионные тесты, CI и локальный pre-commit gate | Полная сборка, CTest, cross-subsystem контракт |
| v38 | Достоверные ETW-измерения дисков по процессам/томам | Только подтверждённые байты, неизвестное не становится нулём |
| v39 | Источники и достоверность температуры CPU | Реальный CPU-датчик приоритетнее платы, `—` при отсутствии |
| v40 | Соответствие AutoScore выбранным дискам | Скрытые тома не влияют на сортировку |
| v41 | Устойчивый автомасштаб истории с пиками | Пики обозначены, малые значения различимы |
| v42 | Согласованное управление графиками/паузой | Единое поведение встроенных и отдельных окон |
| v43 | JSONL для дисков и температуры с качеством источника | Обратная совместимость и регрессионные контракты |
| v44 | Единицы измерения и подписи UI | Понятное различие % системы и MiB/s процесса |
| v45 | Сквозные интеграционные сценарии | Все критичные сценарии и повторяемый JSONL |

Эти задачи уточняют уже работающие сборщики, графики и SQLite — не требуют
переписывать их заново. Реализация каждого патча обсуждается и тестируется
отдельно.
