# Автоматический рейтинг FluxTop 0.2.1

«Авто» — **ранжирование внимания**, а не попытка оценить энергопотребление или
стоимость процесса. Его назначение — показывать одновременно CPU-, GPU-,
RAM-, VRAM- и сетевую нагрузку, не отдавая все строки памяти.

## Научные основания

1. **Multi-Criteria Decision Analysis (MCDA)**: разнородные признаки необходимо
   нормализовать до совместимой шкалы; на результат существенно влияет выбор
   нормализации. Обзор: https://pmc.ncbi.nlm.nih.gov/articles/PMC9433668/
2. **Dominant Resource Fairness** (Ghodsi et al., NSDI 2011): в системах с
   несколькими типами ресурсов полезно рассматривать доминирующую долю.
   Мы используем идею доминирующего ресурса, но **не** алгоритм распределения
   DRF: https://www.usenix.org/conference/nsdi11/dominant-resource-fairness-fair-allocation-multiple-resource-types
3. **EWMA**, Roberts (1959): экспоненциальное сглаживание убирает случайные
   колебания и сохраняет устойчивые изменения. В FluxTop добавлен отдельный
   детектор скачка, чтобы EWMA не замедлял появление оранжевого сигнала.
   Обзор: https://doi.org/10.1080/00401706.1990.10484583

## Шкала (эвристическая, подлежащая калибровке)

- **CPU**: `clamp(3 * % от полной системы, 0, 100)`.
- **GPU**: `clamp(% загрузки движка, 0, 100)`.
- **RAM**: `clamp(0.70 * 100 * WorkingSet / физическая RAM, 0, 100)`.
- **GPU RAM**: `clamp(0.65 * 100 * dedicated / VRAM capacity, 0, 100)`.
- **Rx/Tx отдельно**: `90 * (1 - exp(-bytes_per_sec / (2 MiB/s)))`.

Когда ёмкость RAM или VRAM неизвестна, соответствующий балл становится нулём,
а не вычисляется с фиктивной маленькой ёмкостью. Все остальные ресурсы
продолжают участвовать в рейтинге. Скрытые столбцы исключаются из оценки.

Из значения каждого ресурса формируется сглаженный показатель
`S(t) = 0.65 * current + 0.35 * S(t-1)` (EWMA).

Итоговый рейтинг — `min(100, max(S) + 0.25 * second_best(S))`.
При этом Rx и Tx относятся к **одной** сетевой группе, чтобы сеть не
учитывалась дважды. При большом скачке добавляется ограниченный бонус;
такое значение временно подкрашивается оранжевым (приоритет над красным).
Когда скачок заканчивается, показатель остаётся красным только при
существенной сохраняющейся нагрузке (от 10 баллов).

Порог оранжевой подсветки: 5 баллов всплеска; бонус к рейтингу начинается с 20 баллов. Всплеск определяется отдельной нормализацией разницы
между текущим и предыдущим значением и быстро затухает.
Для процесса используется пара PID + время создания во избежание ложных
срабатываний при переиспользовании PID.

## Ограничения

- Параметры `3`, `0.70`, `0.65`, `2 MiB/s` и пороги **не выведены** из
  экспериментально обученной модели. Это начальная прозрачная настройка.
- Working Set содержит разделяемые страницы: доли разных процессов
  не должны складываться в «потребление системы».
- GPU Engine % и полный CPU % — разные величины; веса нуждаются в реальной
  калибровке на играх, IDE, браузере и задачах локального ИИ.
- Датчики температуры в баллы не включены. Это отдельные индикаторы.
- В режиме «Авто» красный/оранжевый относится к решающему **числу** в строке;
  заголовки окрашиваются по отдельным пользовательским порогам.
