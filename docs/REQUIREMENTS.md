# Требования FluxTop

## Назначение

Помочь пользователю увидеть, какие приложения потребляют ресурсы,
не создавая заметную дополнительную нагрузку. Проект использует идеи
таблицы процессов htop, графиков btop и оверлеев FPS Monitor,
но реализует собственное небольшое нативное ядро.

## Требования к данным

| Показатель | Семантика | Недоступность |
| --- | --- | --- |
| CPU | Доля полной вычислительной мощности системы, 0–100% | Нет предыдущего снимка, нет доступа или смена процесса |
| RAM / Working Set | Физические страницы рабочего набора, включая общие | Нет доступа или завершение процесса |
| Private Bytes | Приватная выделенная память; это не объём физической RAM | Нет доступа |
| GPU | Максимальная загрузка двигателя процесса среди доступных адаптеров | Нет WDDM/счётчиков/валидного измерения |
| Dedicated GPU Memory | Выделенная графическая память процесса по адаптерам | Нет счётчика или экземпляра |
| Сеть | Входящие и исходящие байты/с по процессу, будущий ETW-сборщик | Сборщик выключен или нет прав |
| Дисковый I/O | Будущий отдельный сборщик фактического дискового обмена | Нельзя подменять суммарным process I/O |
| Температура | Показатель устройства, а не процесса | Нет поддерживаемого источника |

Неизвестные значения показываются как `—` в интерфейсе и `null` в экспорте.
Нельзя выдавать отсутствие доступа за нулевую нагрузку.
PID не является устойчивым идентификатором: для снимков используется
пара PID + время создания, для сцен — полный путь EXE.
Первая версия показывает отдельные процессы, без группировки по приложениям.

## Первый работающий этап

Консольный C++20-сборщик без GUI, драйвера и обязательных сторонних библиотек:

1. Периодические снимки доступных процессов, CPU, Working Set и Private Bytes.
2. Опциональный PDH-сборщик GPU и dedicated memory.
3. Сортировка CPU/RAM/GPU/графическая память; TOP N или все строки.
4. Конечное число снимков для воспроизводимых замеров и остановка Ctrl+C.
5. Машиночитаемый локальный экспорт и собственные CPU/RAM/handles/время сбора.
6. Проверка расчётов, ошибок аргументов и короткий запуск на Windows.

На этом этапе нельзя заявлять выполнение общего бюджета с оверлеем и SQLite.

## Независимость обновления от запуска

Updater и монитор выполняются отдельными процессами. При обычном запуске
сначала проверяются обновления, даже если предыдущая версия монитора
не может стартовать. Ошибка EXE, настроек или истории не должна лишать
пользователя автоматического получения нового commit с исправлением.
Целевые подтверждение старта, fallback и сценарии приёмки описаны
в [ADR-0001](decisions/0001-independent-updater.md).

## Оверлей и сцены — последующие этапы

Единая таблица: иконка EXE, название, выбранные метрики. Настраиваются
позиция, размер, масштаб, прозрачность, порядок колонок, сортировка и тема.
Режимы строк: TOP 5/10/20, все доступные, закреплённый список.
Для стабильности строк — задержка перестановок или сглаживание.
Оповещения — пороги, отклонение от скользящего среднего и период подавления.

Для каждого приложения можно задать сцену; при отсутствии совпадения
используется глобальная. Переключение — по событию активного окна.
Требуется учитывать несколько мониторов, DPI и исчезновение монитора.
Окно настроек создаётся по запросу и уничтожается при закрытии.

## Автозагрузка с Windows — этап сцен и трея

Опциональный запуск при входе текущего пользователя, по умолчанию выключен.
Старт в трей без консоли и окна настроек, с сохранённым профилем оверлея.
Нужны задержка запуска, защита от второго экземпляра, включение/выключение
без прав администратора и согласование с проверкой обновлений через Git.
Подробные требования и критерии — в [документе автозагрузки](AUTOSTART.md).
В текущем прототипе функция ещё не реализована.

## Ограничения первой версии

- Windows 10/11 x64; ARM64 и Windows до 10 вне первоначальной матрицы.
- Обычные пользовательские права по умолчанию; защищённые процессы могут быть недоступны.
- Без инъекций, игровых хуков, собственного драйвера и обхода anti-cheat.
- Оверлей рассчитан на оконный/borderless режим; exclusive fullscreen не гарантируется.
- FPS, frame time, сеть, диск и температура не входят в первый сборщик.
- Бюджет ресурсов требует измерений на физическом оборудовании; CI его не доказывает.
