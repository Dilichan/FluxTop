# Прозрачный оверлей и клиент

Оверлей содержит: уменьшенная иконка EXE, имя приложения,
CPU, RAM, GPU, память GPU, сетевые Rx/Tx. Текст белый с небольшой тенью для читаемости.
Заголовок «Приложение» начинается у левого края, над колонкой иконок.
Единственная строка шапки показывает общую нагрузку справа от названия
показателя: `CPU 12.3%`, `RAM 35.1%`, `GPU 4.0%`, `GPU RAM 3.1 GiB`.
Итоги не зависят от TOP:
CPU и RAM в процентах, GPU — загрузку самого занятого движка,
GPU RAM — общий объём dedicated memory адаптеров, Rx/Tx — скорости TCP/UDP.
Rx/Tx — один столбец: `1.2 / 3.4 MiB/s`, приём слева, передача справа.
Обе скорости используют общую единицу, выбранную по большей из них.
В режиме только общих показателей весь оверлей занимает одну строку.
Панель, логотип, название FluxTop, TOP-кнопки, PID и диагностический подвал
в оверлее отсутствуют. Название программы находится в заголовке клиента.

```powershell
.\fluxtop.cmd -NoUpdate --overlay
```

## Настройка в клиенте

- Размер шрифта 10–36 px, ручной ввод числа приложений 1–100,
  сортировка CPU/RAM/GPU/память GPU/Авто/Rx/Tx/Rx+Tx.
- Настройки применяются и сохраняются автоматически. У числовых полей пауза
  300 мс после ввода; неверное значение не применяется, при потере фокуса
  восстанавливается последнее допустимое. Кнопки «Применить» нет.
- Непрозрачность текста и иконок — ползунок 1–100%, фон всегда прозрачен.
- Отдельные флажки CPU/RAM/GPU/GPU RAM и единый Rx/Tx скрывают соответствующие столбцы.
  «Только общие показатели» убирает список и колонку названий. Если снять все
  флажки метрик, остаются общие показатели всех ресурсов без списка приложений.
- Интервал сбора и обновления — ручной ввод от 1 до 10 целых секунд;
  применяется без перезапуска сборщиков и сохраняется вместе с настройками.
- Включение иконок, показ/скрытие оверлея и режим перемещения мышью.
- Статистика процесса FluxTop, состояние сборщиков и ошибки отображаются здесь.
- Закрытие клиента уничтожает окно настроек, оставляя оверлей и трей.
- Автозапуск при входе в Windows с запросом UAC: [AUTOSTART.md](AUTOSTART.md).

«Авто» рассчитывает рейтинг по текущей нормализованной нагрузке CPU, RAM,
GPU, VRAM и сети, дополняя его короткими всплесками. Каждый столбец
окрашивается независимо; скрытые показатели не влияют на рейтинг.
В первой строке отображается приложение активного foreground-окна Windows.
При этом остальные строки остаются в AutoScore-порядке. Смена окна обрабатывается
по событию, а сбор ресурсов идёт с пользовательским интервалом.
Режимы Rx и Tx сортируют по соответствующей скорости, Rx/Tx — по сумме.
Неизвестные значения не подменяются нулём.

Двойной клик по трею или Ctrl+Alt+F9 открывает клиент.
Ctrl+Alt+F10 показывает/скрывает оверлей, если сочетания удалось зарегистрировать.
Меню трея содержит открытие клиента, показ/скрытие и выход.
В обычном режиме клики проходят сквозь оверлей. Для перемещения включите
соответствующий режим в клиенте, перетащите оверлей за текст и выключите режим.
Если строки не помещаются по высоте, в режиме перемещения доступна прокрутка.

Настройки сохраняются в %LOCALAPPDATA%\FluxTop\overlay.ini.
Аргументы --top, --sort и --font-size имеют приоритет над сохранёнными значениями.
--font-size N принимает 10–36 и требует --overlay. Для изолированных проверок
FLUXTOP_OVERLAY_SETTINGS задаёт путь к отдельному INI.

## Многопроцессные приложения

Снимок Windows собирается по каждому PID. Только для оверлея процессы
объединяются в приложения по нормализованному **полному пути EXE**.
В отличие от одного дерева PID/PPID это включает отдельные корни Chrome,
Edge, Firefox, VS Code, Electron и других программ с одинаковым EXE-путём.
Если путь отсутствует, разрешено лишь проверенное родство PID/PPID с учётом
порядка создания процессов и совпадения имени при отсутствии обоих путей.
Совпадение **только имени** не объединяет независимые экземпляры.

Отдельные профили и окна одного EXE объединяются в одну строку. Разные пути
одного имени (например, установленные рядом стабильная и тестовая сборки)
остаются отдельными группами. Подсчёт по путям не зависит от производителя CPU
или видеокарты.

CPU, Working Set, GPU RAM, Rx и Tx суммируются по отдельным PID без
дублирования PID. GPU% — **максимум** нагрузки среди процессов группы;
складывать проценты разных движков некорректно. Working Set может включать
разделяемые физические страницы, поэтому это не размер уникальных страниц в RAM.
Недоступные значения остаются неизвестными. Разница между одним замером
Get-Process и оверлеем может быть также связана с временем замеров и доступом
к процессам; точное равенство не гарантируется.

Авто-рейтинг и всплески рассчитываются по агрегированным приложениям. Окно
любого дочернего или независимого процесса группы закрепляет всю группу первой
строкой. SQLite/JSONL и исходный снимок сохраняют детальные записи по PID.

## Рендеринг и жизненный цикл

Сборщики работают в отдельном потоке; mailbox хранит только последний снимок.
Оверлей рисуется Direct2D/DirectWrite в ARGB-поверхности и выводится через
UpdateLayeredWindow. У фона нулевая альфа; буквы и иконки имеют собственную альфу.
Полупрозрачной прямоугольной панели нет. Перерисовка событийная, без 60 FPS.

При скрытии оверлея графические ресурсы освобождаются. Сборщики и запись
истории продолжаются даже при закрытом клиенте. Между началом соседних сборов
выдерживается выбранный интервал; при слишком долгом сборе нет цикла догоняющих
замеров. UI получает последний снимок без очереди старых обновлений.
Запись всех процессов и счётчик строк описаны в [HISTORY.md](HISTORY.md).

## Иконки приложений

Иконка извлекается из EXE в фоновом потоке, уменьшается до 32×32, кодируется
в PNG и хранится BLOB-ом в %LOCALAPPDATA%\FluxTop\icons.db.
Используется системная SQLite Windows (winsqlite3.dll), без отдельного сервера.

- Размер БД и число сохранённых путей не ограничены приложением; автоматической
  чистки по количеству записей нет. Кеш страниц SQLite в RAM — 128 КиБ.
- Ключ: EXE-путь, время изменения и размер файла. Изменение EXE обновляет запись
  при следующей загрузке иконки из дискового кеша.
- В памяти максимум 64 декодированных изображения — около 256 КиБ пикселей.
- Очередь ограничена; отрицательные результаты тоже кешируются.
- При недоступной БД используется память; при недоступном EXE — системная иконка.
- БД содержит локальные EXE-пути, не отправляется по сети и исключена из Git.

Для тестов FLUXTOP_ICON_DB задаёт путь БД внутри build/.
При измерении бюджета учитываются WIC, SQLite, шрифты и все потоки процесса.
Лимит 50 МиБ относится к активном оверлее при свёрнутом в трей клиенте.
Открытый клиент измеряется отдельно. Сворачивание и закрытие окна клиента
освобождают его ресурсы, сохраняя оверлей и трей. История и кеши разделены:
см. [HISTORY.md](HISTORY.md).

## Границы

Консольный режим и JSONL сохраняются. --overlay несовместим с --jsonl;
--samples N завершает диагностический UI-запуск после N снимков.
Сцены, экран аналитики и протокол ready updater-а ещё не завершены.
Оверлей работает в оконном/borderless режиме без внедрения кода в игры.

## Показатели и сеть

CPU всей системы: GetSystemTimes; RAM: GlobalMemoryStatusEx.
GPU всей системы: сумма процессов по каждому PDH GPU Engine и максимум
между движками (0–100%), без сложения процентов независимых движков.
Общая GPU RAM берётся из GPU Adapter Memory, без суммирования строк процессов.
Память отдельного процесса: D3DKMTQueryVideoMemoryInfo, CurrentUsage локального
сегмента по адаптерам/физическим узлам. На UMA локальный сегмент может быть
системной памятью. JSON-имя dedicated_gpu_bytes сохранено для совместимости.
Недоступный запрос показывает «—», не прошлое значение или фиктивный ноль.

Rx — приём, Tx — передача; единицы B/s, KiB/s, MiB/s. Используется отдельная
системная ETW-сессия только с NETWORK_TCPIP: TCP/UDP, IPv4/IPv6. Учитываются
события Send/Recv; LAN и loopback входят в показатели. Это не счётчик оплаты
интернет-провайдера: VPN, прокси и локальные сервисы могут менять атрибуцию.
Пакеты и адреса не сохраняются; только суммы байтов по PID за интервал.
Есть задержка доставки ETW около секунды. PID сверяется с временем создания.
Системный итог включает и процессы, которых уже нет в текущем списке.
При недостаточных правах сеть имеет статус administrator-required, при потере
событий или ошибке разбора — incomplete; значения показываются неизвестными.
Восстановление после ошибки — перезапуск сборщика/программы.
--no-network отключает ETW. При завершении сборщика его ETW-сессия закрывается.
Память её буферов ограничена настройками 2–8 × 64 КиБ
без отдельных буферов на каждый CPU; реальную стоимость измеряем отдельно.
После аварии следующий сборщик очищает только сессии FluxTop с отсутствующим
владельцем или другим временем создания PID. Живые/недоступные владельцы
и чужие ETW-сессии не останавливаются.

Интеграционный тест build/ninja/fluxtop_network_tests.exe запускают с правами
администратора; он создаёт только loopback TCP/UDP IPv4/IPv6. Без повышения
CTest отмечает его пропущенным (код 77).

Источники: [GPU memory counter issue](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/gpu-process-memory-counters-report-wrong-value),
[D3DKMTQueryVideoMemoryInfo](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmthk/nf-d3dkmthk-d3dkmtqueryvideomemoryinfo),
[system ETW sessions](https://learn.microsoft.com/en-us/windows/win32/etw/configuring-and-starting-a-systemtraceprovider-session).


## Автоматическая сортировка (0.2.1)

Рейтинг «Авто» берёт максимум нормализованной текущей нагрузки и всплеска по каждому видимому показателю.
Высокая постоянная нагрузка остаётся в списке после прекращения роста.
Небольшое затухание прошлого приоритета действует только пока показатель остаётся значимым.
Процессы сопоставляются по PID и времени создания; при повторном использовании PID предыдущая история игнорируется.
Цвет каждого числового показателя CPU/RAM/GPU/GPU RAM определяется его собственной фактической загрузкой, а не местом в рейтинге. Оранжевый всплеск выделяется независимо в том столбце, где произошёл скачок.
Другие режимы сортировки не окрашивают строки; общие показатели в заголовке имеют собственные цветовые пороги.
## Цвета и температуры в заголовке (0.2.1)

CPU/RAM/GPU окрашиваются по общесистемному проценту: 0–<50 зелёный,
50–<70 жёлтый, 70–100 красный. GPU RAM окрашивается только когда известны
использованный объём и ёмкость dedicated VRAM; показывает только занятый объём в GiB.
Rx/Tx не окрашивается процентными порогами, так как это байты/с.
Температуры: <65°C зелёный, 65–80°C жёлтый, >80°C красный.
GPU температура — WDDM D3DKMT, CPU температура — HWiNFO Shared Memory,
если пользователь отдельно установил и включил HWiNFO. Недоступное — прочерк.
HWiNFO не поставляется вместе с FluxTop. Значения разных GPU могут отличаться;
пока для шапки используется наибольшая валидная температура.

Оранжевым отмечается только непосредственный всплеск, который определил
авторейтинг; сохраняющаяся нагрузка выделяется красным. Скрытый показатель
не влияет на рейтинг. Видеопамять по процессам может включать общие/разделяемые
ресурсы и не обязана суммироваться до общесистемного использования GPU.
## Отдельные переключатели цветов (0.2.1)

В клиенте есть два независимых флажка:

- «Окрашивать общие показатели» включает/выключает цветовую индикацию загрузки
  системы и температуры CPU/GPU в первой строке. При выключении значения белые.
- «Окрашивать строки оверлея» включает/выключает цвета только в строках
  процессов; сортировка «Авто» от этого не меняется.

Каждый доступный показатель CPU/RAM/GPU/GPU RAM окрашивается независимо от сортировки:
0–<50% использования — зелёный, 50–<70% — жёлтый, от 70% — красный.
Для CPU/GPU используется исходный процент нагрузки; для RAM/GPU RAM — доля
ёмкости физической памяти или выделенной VRAM. Вес AutoScore на цвет не влияет.
Значимый всплеск (оранжевый) временно перекрывает собственный цвет метрики, даже когда не она определяет рейтинг. Детекция всплеска используется в режиме «Авто».
Пока нет знаменателя для Rx/Tx, их постоянный трафик остаётся белым;
всплески приёма/передачи отображаются оранжевым на соответствующем числе.
Неизвестные показатели не окрашиваются.

Флажки по умолчанию включены и сохраняются отдельно в overlay.ini
как header_colors и row_colors. Данные измерений и рейтинг не изменяются.
## Закрепление активного окна в «Авто»

В «Авто» первый слот занимает группа приложения, которой принадлежит активное
foreground-окно Windows. Поддерживаются окна любого дочернего или другого
процесса **той же EXE-группы**. Остальные приложения сохраняют порядок AutoScore.
Переключение окон происходит по EVENT_SYSTEM_FOREGROUND без постоянного опроса;
снимки данных продолжают поступать с обычным интервалом.
При отсутствии PID в снимке действует стандартный рейтинг. Правило не
действует в других режимах сортировки. Закреплённая строка остаётся видимой
при прокрутке и не дублируется.


## Настройка геометрии столбцов

Ширины и отступы таблицы задаются **только в** `include/fluxtop/overlay_layout.hpp`, в `overlay_layout`. 
Поле `metric_widths` содержит CPU, RAM, GPU, GPU RAM и Rx/Tx; также доступны `application_width`, `icon_width`, `column_gap` и отступы по краям.

Функция `calculate_overlay_columns()` единым алгоритмом вычисляет координаты ячеек и общую ширину окна. 
Скрытых минимальных ширин и дублирующихся коэффициентов в `src/overlay.cpp` нет. 
Изменения C++ требуют пересборки Release; ранее установленный EXE не обновляется автоматически.
