# v54 — постоянные испытания стабильности

Проверки входят в исходники и CTest. Одноразовый ручной запуск без сохранённого
теста не считается покрытием. Автоматический набор не переводит Windows в сон,
не меняет установленные драйверы и не взаимодействует с защищённым рабочим столом UAC.

## Запуск автоматического набора

Из Developer PowerShell, открытого **от администратора**, после Release-сборки:

```powershell
ctest --test-dir build/v54 -C Release --output-on-failure --parallel 1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-Stability.ps1 -BuildDirectory build/v54 -Repetitions 5
```

Для обычного preset вместо `build/v54` укажите `build`. Скрипт сохраняет хеш
монитора, параметры окружения, результат и журнал **каждой** попытки в
`build/v54/stability-<UTC>/`. Ошибка первого прогона не стирается успешным повтором.
Пропуск обязательного административного теста считается ошибкой runner.
`tools/Check-Regression.ps1` также проверяет наличие обязательных поведенческих
тестов, включая новые испытания v54, и требует административный запуск.

Только выбранные проверки и более длинный совместный сбор:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-Stability.ps1 -BuildDirectory build/v54 -TestPattern '^(collector_stability|sensor_recovery)$' -Repetitions 1 -SoakSamples 60
```

`collector_stability` создаёт три экземпляра настоящего Sampler последовательно;
каждый получает указанное число отсчётов с интервалом 500 мс. Предел параметра
runner — 60, чтобы длинный прогон оставался в пределах CTest timeout 120 с.
Прямой запуск `fluxtop_collector_stability_tests.exe <каталог> <число>` допускает
до 7200 отсчётов для длительного стендового испытания вне этого timeout.

GPU/FPS/температуры зависят от драйверов и доступных провайдеров. Совместный
тест включает сборщики, проверяет валидность полученных значений и печатает
статусы/покрытие. Отсутствие пригодных событий Present или датчика не означает измеренный ноль
и не доказывает успешное получение FPS/температуры. `sensor_recovery` возвращает
77, если на стенде нет необходимого Intel/PawnIO/модуля: это явно непроверенная
аппаратная возможность, а не успешное восстановление.

## Сценарии, требующие пользователя

Все четыре сценария зарегистрированы в CTest с меткой `interactive` и по умолчанию
отключены. Запускайте нужный скрипт отдельно, когда готовы выполнить действие.
Для осознанного запуска через CTest существует опция
`-DFLUXTOP_ENABLE_INTERACTIVE_TESTS=ON`; запускайте **один** сценарий через `-R`.
Она не предназначена для CI и обычного полного CTest.

В обычном, **не повышенном** PowerShell, после закрытия монитора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-WindowsLifecycle.ps1 -Scenario UacCancel -LauncherPath build/v54/package/Release/FluxTop.exe -AllowInteractive
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-WindowsLifecycle.ps1 -Scenario StartMenu -AllowInteractive
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-WindowsLifecycle.ps1 -Scenario Autostart -AllowInteractive
```

Для UAC выберите «Нет». Для «Пуска» запустите установленный FluxTop через меню
и подтвердите UAC. Autostart вызывает уже существующий Startup-ярлык, ждёт
штатную задержку и требует один монитор; тест не создаёт ярлыков и не меняет
StartupApproved. Проверка настоящего входа в Windows остаётся отдельным
стендовым наблюдением. Предварительно включите автозапуск в клиенте.

В повышенном PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-WindowsLifecycle.ps1 -Scenario SleepResume -MonitorPath build/v54/fluxtop.exe -AllowInteractive
```

Скрипт запускает собственный консольный сборщик, просит вручную усыпить и
разбудить ПК, затем проверяет данные после пробуждения. Он завершает только
созданный им процесс и сохраняет его JSONL и журнал. Результат каждого сценария
записывается в `build/lifecycle/<сценарий>-<UTC>/result.json`, включая ошибки.

## Найденные регрессии

- Общая bootstrap-блокировка позволяла частной установке молча завершиться
  без результата при работающем другом launcher. Частные каталоги получили
  отдельные стабильные блокировки; занятость возвращает `ERROR_BUSY`.
- Задержка `--autostart` удерживала блокировку до запуска: ожидание перенесено
  перед её захватом. `launcher_stability` проверяет оба сценария.
- После потери общей ETW-сессии сборщики не восстанавливались. Теперь владелец
  закрывает обе CPU/disk-ветви, заменяет сессию и начинает новую базу. Network
  восстанавливается независимо. Повторы ограничены задержкой 3–60 секунд;
  недостоверные интервалы не становятся нулевыми или «готовыми».
- При очистке сетевой сессии завершившийся процесс с ещё открытым handle ошибочно
  считался живым. `etw_recovery` держит такой handle и проверяет очистку.
- При нагрузке воспроизведены потери ETW. Общий пул 16-КиБ буферов резервирует
  `max(256, 2 × LP)` и ограничен 2048 буферами (32 МиБ); потеря всё равно явно
  отмечается и запускает восстановление, не скрывается повтором теста.
- Ninja не учитывал заголовки при локализованном MSVC. Проба определяет настоящий
  `/showIncludes`-префикс в Windows ANSI и передаёт Ninja корректный UTF-8.
  Регрессия ABI воспроизвела `0xC0000409`. Это доказанная отдельная причина,
  а не утверждение о происхождении всех прежних аварий.
- Предел 250% в старом живом CPU-тесте не учитывал собственные потоки ProcessTrace
  в том же PID. Вместо этого проверяются непересекающиеся окна и суммарное время
  по независимому GetProcessTimes; проверка двойного учёта сохранена.

## Локальные результаты 23.11.2026

- Release x64 собран MSVC. Ninja теперь видит 20 непосредственных заголовочных
  зависимостей `sampler.cpp` вместо прежних 0; `build_dependencies` проходит.
- Административный полный прогон до последнего расширения набора: **59/59**,
  96,24 с; четыре интерактивных сценария отключены. Доказательства:
  `build/v54/stability-20261123-192431-384/full.log`.
- В том же каталоге сохранены **5/5** повторов `cpu_etw_live`,
  `installation_fixture`, `launcher_stability` и `etw_recovery`.
- При расширении `history_crash` обнаружена ошибка очистки самого fixture:
  открытый reader мешал удалению каталога. Неудачная пятая попытка сохранена
  в `history-crash-5.log`; читатель теперь закрывается до удаления.
  Исправленный тест повторён **5/5** с успехом.
- После последних изменений Release повторно собран; **27/27** затронутых
  автоматических контрактов прошли за 5,03 с (`build/v54-unit-final.log`).
- После отменённого UAC следующий разрешённый запуск был прерван отключением
  питания: в `stability-20261123-200420-185` нет итогового результата, он не
  считается успешным прогоном.
- После восстановления питания заключительный административный набор прошёл
  **61/61**, **0 ошибок, 0 skips**, 180,81 с. Четыре интерактивных сценария
  остались отключены. Итоги и вывод каждого теста сохранены в
  `build/v54/stability-20261123-200724-419/selected-1.log` и `selected-1.xml`;
  окружение и SHA-256 монитора — в `environment.json`.
- `collector_stability`: три последовательных экземпляра Sampler, по 60
  отсчётов, 97,57 с суммарно. GPU и сеть — ready; Intel DTS — ready,
  доступны температуры всех 24 физических ядер, CPU Package берётся из
  `intel-dts-pawnio`. CPU ETW выдаёт готовые/частичные окна и явно отмечает
  ожидание доставки нового окна. Нормальное завершение и контроль дескрипторов
  пройдены. Working Set в конце циклов: 29,5 / 31,5 / 35,4 МиБ; это измерение
  тестового Sampler, а не подтверждение лимита для всего клиента/оверлея.
- `sensor_recovery`: **passed**, 4,53 с — частная копия без IntelMSR сохраняет
  топологию и неизвестные температуры, после возвращения модуля получает
  живые температуры без перезапуска сборщика. Установленный драйвер не менялся.
- Дополнительно подтверждены `admin_required` (код 740 обычного пользователя),
  `cpu_etw_live` (24,19 с), `etw_recovery` (16,58 с), `history_crash` (0,61 с)
  и `build_dependencies` (6,15 с). FPS в совместном fixture не получен
  (`fps_known=0`); получение FPS настоящего рендерящего приложения этим
  прогоном не подтверждено.

Первый базовый прогон и промежуточные ошибки также сохранены в соседних
`stability-*`: в частности, первоначальная потеря 7108 событий ETW и прежний
неверный порог CPU-теста. Последующий успех не стирает эти наблюдения.
Настоящий отказ UAC, «Пуск», вход в Windows и сон в текущем автоматическом
прогоне не выполнялись. Визуальная приёмка остаётся за пользователем.
